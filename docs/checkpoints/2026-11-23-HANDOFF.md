## 5. Protocolo obligatorio de producción
1. Leer este cierre y los documentos rectores antes de intervenir. Abrir los adjuntos reales, no depender de memoria ni de descripciones parciales.
2. Separar requisitos obligatorios, libertad creativa autorizada y elementos bloqueados. Un cambio pedido no autoriza reconstruir otra sección, alterar CMS, backend, diseño o código aprobado.
3. Usar la última fuente canónica. No recuperar versiones retiradas. Evitar diagnósticos repetitivos y ciclos de ensayo sin criterio; ejecutar el objetivo solicitado.
4. Para imágenes, comparar visualmente cada resultado con la muestra antes de declararlo final: relación de aspecto, encuadre, porcentaje del sujeto, actividad específica, superficie, tonalidad, seguridad y uniformidad. No presentar primeros planos como planos generales; no entregar variantes que incumplan requisitos conocidos como si fueran finales.
5. Para código, entregar archivo completo cuando se solicite, sin parches fragmentados; mantener el diff dentro del alcance. Verificar funcionamiento en Preview/Publish cuando exista acceso y distinguir pruebas reales de hipótesis.
6. Antes de escribir en Git/Wix, comprobar destino y estado; guardar únicamente cambios autorizados. No borrar historia, hacer force-push ni reabrir bloqueos. Después de escribir, leer de vuelta y verificar archivos modificados. No prometer instalaciones, sincronizaciones ni pruebas no ejecutadas.
7. Estados: PROPUESTA / VERIFICADO / APROBADO / BLOQUEADO. Solo el usuario aprueba. Un cierre de sesión no implica aprobación de pendientes.
